A worked case study

Estimating and comparing the toxicity of seven herbicides

Background

The posterior draws a Bayesian fit produces are useful well beyond a point estimate. They support the study of synergistic and antagonistic effects (Fisher et al. 2019; Flores et al. 2021), the propagation of endpoint uncertainty (Charles et al. 2020; Gottschalk and Nowack 2013), and tests of hypotheses of no effect (Neal 2006).

compare_posterior() uses them to compare fits: differences in a threshold estimate such as the NEC, NSEC or an ECx, or differences across a range of predictor values.

The data

Earlier modules used simulated data. This one works through a real analysis: estimating no-effect concentrations for a set of herbicides and comparing their relative toxicity.

The data are from Jones and Kerswell (2003) and ship with bayesnec.

The response is the maximum effective quantum yield, \(\Delta F / Fm'\), of symbiotic dinoflagellates in the tissue of the coral Seriatopora hystrix, calculated from chlorophyll fluorescence measured with a DIVING-PAM fluorometer (Jones and Kerswell 2003; Jones et al. 2003). Corals were exposed for 10 hours to eight herbicides at concentrations from 0.3 to 1000 \(\mu g L^{-1}\). Ioxynil is excluded here because it produced no adequate response at the highest concentration, leaving seven.

Provenance of these fits

Seven herbicides fitted against the decline set is 14 equations each, and takes hours. These fits are therefore not run when this page is built. They are produced by scripts/generate_herbicide_fits.R, which writes the compact results this module reads. The fitted objects themselves are far too large to keep — the 2023 equivalent was 451 MB.

The code shown below is the code that was run. It is displayed rather than executed, and every result on this page comes from that run.

A single herbicide

Taking ametryn first. The concentration is log transformed before fitting, both because it stabilises the fit and because the concentration series is logarithmic by design. There is little evidence of hormesis in these data, so the decline set is used rather than the full set.

ametryn <- herbicide |>
  mutate(concentration = log(concentration)) |>
  filter(herbicide == "ametryn")

manecfit_ametryn <- bnec(fvfm ~ crf(concentration, model = "decline"),
                         data = ametryn, seed = 17)

Every argument other than the model set is left at its default. bayesnec selects a beta distribution for the response, uses the identity link, and drops neclin and ecxlin from the decline set because they are not suitable for a zero-bounded distribution.

The complete set of herbicides

The same call is applied to each herbicide in turn.

manecfit <- herbicide |>
  mutate(concentration = log(concentration)) |>
  split(f = ~ herbicide) |>
  purrr::map(function(x) {
    bnec(fvfm ~ crf(concentration, model = "decline"), data = x, seed = 17)
  })

Screening the model sets

Each of the seven sets is screened on all three sampler diagnostics before it is used, as module 4 describes.

sampling <- purrr::imap_dfr(manecfit, function(fit, nm) {
  check_sampling(fit) |> mutate(herbicide = nm, .before = 1)
})

cleaned_fits <- purrr::map(manecfit, screen_models)

screen_models() drops the equations that failed and reports which went and why. Do not reach for rhat(fit)$failed in its place: rhat() on a bayesmanecfit returns a list keyed by model name, each element holding the R-hat values and a logical failed, so $failed on the list itself is NULL and silently drops nothing. The earlier version of this module had that defect.

The full table is kept rather than only the failures, because the thresholds applied are part of what has to be reported:

sampling <- read.csv("data/herbicide_sampling.csv")

sampling |>
  summarise(equations = dplyr::n(),
            removed = sum(failed),
            .by = herbicide) |>
  kable()

Equations that produced no draws at all are a different failure, and are reported separately by failed_models():

Module 4 sets out why the two are worth separating: an equation short of draws needs more of them, while an equation the design cannot support needs reporting as excluded.

Model weights across herbicides

modstats <- read.csv("data/herbicide_mod_stats.csv")

modstats |>
  mutate(wi = round(wi, 3)) |>
  select(herbicide, model, wi) |>
  pivot_wider(names_from = herbicide, values_from = wi) |>
  kable()

The best-fitting equations differ substantially between herbicides. Few show much weight on the threshold models. Among the smooth equations the weights vary widely, with support for more than one in every case.

That is the argument for model averaging in a sentence: there is no single equation that is right for these data, the best one differs by herbicide, and selecting one would discard the uncertainty about which. Averaging propagates it into the estimates instead.

Some models failed to fit under the default settings for every herbicide. Custom priors or initial values would likely recover them, but with a large number of well-fitting models already in each set, doing so is unlikely to change the inference.

The toxicity estimates

The value reported for each herbicide is a model-averaged posterior combining the NEC parameter from the threshold equations with the NSEC from the smooth ones, which is what module 3 described. It is labelled N(S)EC for that reason.

read.csv("data/herbicide_estimates.csv") |>
  transmute(Herbicide = herbicide,
            `Estimate` = signif(estimate, 3),
            `Lower 95%` = signif(lower, 3),
            `Upper 95%` = signif(upper, 3)) |>
  kable()

These are the estimates that would enter a guideline derivation. In Australia that is the Australian and New Zealand Water Quality Guidelines (ANZG 2018). The NEC has been the established preference for some time (Warne et al. 2015; Warne et al. 2018), and the 2025 revision of the derivation method (Warne et al. 2025) places the NSEC alongside it: the two are now the most preferred statistical estimates, with an ECx at x of 10 or less in the tier below them.

That has a practical consequence for a table like the one above. Because the NSEC sits in the preferred tier, the condition attached to it applies, and an NSEC whose measured effect size exceeds 20% should probably not be used to derive a guideline value. Module 3 covers the ECNSEC, which is the quantity that measures it, and an analysis reporting an N(S)EC for guideline use should report that alongside.

Comparing the posteriors

compare_posterior() extracts the weighted posterior for each fit so they can be compared directly, rather than by asking whether intervals overlap.

comparison names the quantity compared, and takes "nec", "n(s)ec", "nsec", "ecx" or "fitted". "n(s)ec" is used here because these sets mix threshold and smooth equations, so the weighted no-effect posterior is a mixture of both kinds of estimate. Asking for "nec" would compare the threshold parameter alone, over the equations that have one, which is a different quantity and would be a different table.

post_comp <- compare_posterior(cleaned_fits, comparison = "n(s)ec")
post <- read.csv("data/herbicide_ne_posterior.csv")

ggplot(post, aes(x = concentration, group = model,
                 colour = model, fill = model)) +
  geom_density(alpha = 0.3) +
  scale_x_continuous(trans = "log", breaks = c(0.3, 1, 3, 10, 30),
                     labels = c(0.3, 1, 3, 10, 30)) +
  labs(x = expression("Concentration ("*mu*"g/L)"), y = "Density",
       colour = "Herbicide", fill = "Herbicide") +
  theme_classic()

Irgarol, diuron and ametryn are the most toxic and are similar to one another, their densities overlapping substantially. Tebuthiuron is the least toxic, followed by simazine and atrazine, with hexazinone intermediate.

Probabilities of difference

Overlapping densities are a visual impression. compare_posterior() also returns the probability that one estimate is lower than another, computed from the draws.

read.csv("data/herbicide_prob_diff.csv") |>
  separate(col = comparison, into = c("herbicide", "against"), sep = "-") |>
  pivot_wider(names_from = against, values_from = prob) |>
  kable()

This is the practical advantage of having the posterior rather than an interval. The question of whether A is more toxic than B is answered with a probability computed from the draws, without a significance test, and it propagates the uncertainty in the curve shape as well as in the parameters.

The parameters behind the estimates

summary() reports the weights and the no-effect estimate and no parameter estimates at all. curve_params() returns those, one row per parameter per equation, with the model weight beside each row:

read.csv("data/herbicide_curve_params.csv") |>
  filter(herbicide == "ametryn") |>
  transmute(Model = model, Parameter = parameter,
            Estimate = signif(Estimate, 3),
            `Lower 95%` = signif(Q2.5, 3),
            `Upper 95%` = signif(Q97.5, 3),
            Weight = round(wi, 3)) |>
  kable()

Nothing is averaged across the equations, because they do not share a parameter list: only the threshold equations estimate nec, and the three-parameter equations have no bot. Averaging a parameter over whichever equations happen to estimate it would average over a different subset of the set for each parameter. The weight beside each row is what makes the table readable, since a row holding a thousandth of the weight describes the averaged curve hardly at all.

xform = exp was applied when these were generated, and it reaches nec and ec50 and no other parameter, because those two are on the predictor axis while top, bot and beta are levels of the response or shape parameters.

Reporting the analysis

The estimates above are the output. What follows is what has to accompany them, because almost every number in this module is a property of a decision as much as of the data.

State the data as analysed: the response, the bounds of its distribution, and any value altered to bring it inside the family’s support. bnec_record() reports the last of these in its substitutions element.

State the family and how it was chosen. Here bayesnec inferred a beta distribution from a continuous response bounded by 0 and 1. For a count out of a total, report the dispersion screen of module 5 and the probability it returned.

State the candidate set as fitted: the set requested, the equations excluded before fitting and why, and any equation that failed to fit at all. bnec_record() returns the first three and failed_models() the last.

State the sampler settings, including the number of retained draws rather than iter alone, because two of the three diagnostic cutoffs are absolute counts read against them.

State the diagnostic thresholds, all three of them. They are choices, they determine what was excluded, and check_sampling() allows each to be changed.

State which equations were excluded and why, naming the threshold each failed, and distinguishing an equation that would pass with more draws from one the design cannot support.

State the estimate settings: sig_val, which sets the NSEC reference and defaults to 0.01; type, which sets what an ECx is measured against and defaults to "absolute"; resolution, the number of grid points a crossing is interpolated on, which defaults to 200; and any xform used to return an estimate to the measured scale.

State the estimates with their intervals and the weights of the retained equations, and the parameters of the fitted curve that the estimates were read from.

One of those deserves emphasis here because this analysis was fitted on a transformed predictor. Every estimate is returned on the scale it was fitted on unless xform says otherwise, and a logged value can land in the same numeric range as a concentration and pass unremarked. Reporting a logged value as a concentration understates the threshold by a factor of e for every unit on the logged scale, and only a negative logarithm announces the error. A reported value has to state the scale it is on.
